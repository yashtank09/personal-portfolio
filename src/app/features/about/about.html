Principles I build with.

Make the domain understandable.

Clear boundaries and names make software easier to reason about. I favor an architecture that fits the problem and can evolve with it.

Measure before optimizing.

SQL, API responses, and caching are useful places to improve performance when evidence points to a bottleneck.

Build for people on both sides.

A useful interface matters, and so does the experience of the engineer who maintains it. Reliability, clear APIs, and readable code support both.
